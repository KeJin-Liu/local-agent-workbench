# p0.6 富媒体技术方案

## 现状（相对 p0.5）

- `Message` 仅有 `content: string`，无 attachments。
- 已有 multipart：`POST /api/avatars` + `data/avatars`，可复用解析器。
- 发送：`POST /api/conversations/:id/send` JSON `{ text }`；composer 纯 textarea。
- UI 定稿：`agent-chat-ui/rich-media.html` + styles（`.attach-btn` / `.preview-chip` / `.bubble-media` / `.lightbox`）。

## 数据模型

```ts
type MessageAttachment = {
  id: string
  kind: 'image' | 'file'
  name: string
  mime: string
  size: number
  path: string // /media/files/<id>.<ext>
}
// Message.attachments?: MessageAttachment[]
```

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/media` | multipart `file`，≤10MB；返回 `{ attachment }` |
| GET | `/media/files/:name` | 静态预览 |
| GET | `/media/files/:name?download=1` | 下载（Content-Disposition） |
| POST | `/api/conversations/:id/send` | 增 `attachmentIds?: string[]`；`text` 可空（须有附件） |

## 落盘

- 目录：`data/media/`
- 文件：`<uuid>.<ext>` + `<uuid>.json` meta

## 发送流程

1. 前端选文件 → 立即 `POST /api/media`（composer 预览 chips）
2. 发送时 JSON：`{ text, attachmentIds }`（先上传再发消息，不挡纯文字）
3. 编排器把 attachments 写入用户消息；给模型的 content 追加 `[图片: name]` / `[附件: name]` 标签（本阶段不做视觉多模态）

## 不挡主聊

- 无附件：与 p0.5 完全同一路径
- 上传失败只影响该 chip；文字仍可发
- lightbox / 下载不阻塞发送与取消

## 测试要点

- 上传 PNG / md；拒绝 SVG；路径穿越 404
- 带 `attachmentIds` 发送后 thread 回读含 attachments
- 纯文字 send 无 attachments 字段
- 原有测试保持绿
