## 1. 现状结论（可复用度高）

### 1.1 后端提案服务 — 已齐

| 能力 | 位置 | 行为 |
| --- | --- | --- |
| 领域类型 | `domain/types.ts` `Proposal` / `ProposalKind`=`skill\|mcp\|task` | `status: pending\|confirmed\|cancelled`；确认前本体不在 skills/mcp/tasks |
| 服务 | `app/proposals.ts` | `stage` / `confirm(scope, friendIds)` / `cancel` / `listPending` |
| 工具 | `PROPOSE_TOOL` = `workbench_propose` | 只 stage 确认卡，描述写明「确认前不会保存」 |
| 编排注入 | `session/orchestrator.ts` + `server.ts` | 有 `options.propose` 时挂工具；系统提示要求「确认前不要说已保存」 |
| HTTP | `GET …/conversations/:id/proposals`；`POST /api/proposals/:id/confirm`；`POST …/cancel` | confirm body：`{ scope, friendIds? }` |
| 单测 | `test/proposals.test.ts` | 未确认无本体；取消丢草稿；好友不存在失败不写任务 |

**事务边界**：`confirm` 在单次 `database.update` 内 `writeTask|writeSkill|writeMcp` **然后** 才把 proposal 标 `confirmed`。`database.update` 对 `structuredClone` 草稿操作，mutator 抛错则不写 `cache`/不 `persist` → 本体零写入。外层 catch 另开 update 只记 `proposal.error`，仍保持 `pending`。符合「失败整笔回滚」。

### 1.2 与相邻路径的区分（勿混）

| 路径 | 触发 | 落库门闩 | 作用域 UX |
| --- | --- | --- | --- |
| **模型提议** `Proposal`（本包） | 工具 `workbench_propose` | 确认卡确认才写 skill/mcp/task | `.confirm-card` 全局 \| 指定好友 |
| **系统建议技能** `SkillSuggestion` | `detectSkillSuggestion`（近 7 天重复 ≥3） | accept 才写 skills；dismiss 不写 | 同 `.scope-opt`（`skill-suggest-card.tsx`） |
| **手动保存技能** | 聊天「保存为技能」 | 表单确认 | 默认挂好友 |
| **MCP 市场启用** | 市场「启用」sheet | `mcp.enableFromCatalog(scope, friendIds)` 即时写服务器配置 | 同 scope UX，**不是** Proposal |
| **任务页手动建** | `tasks` upsert | 直接写 | 任务自带 friendId |

p0.8 **只验收会话内模型提议**（Proposal）；SkillSuggestion / 市场启用保持原状，共用视觉 token 即可。

### 1.3 Message / 工具如何触发「提议」

1. 用户发消息 → orchestrator 组装 tools = MCP catalog +（若注入）`PROPOSE_TOOL`。  
2. 模型非流式 tool-loop 调用 `workbench_propose({ kind, name, summary?, body?, … })`。  
3. `server.ts` `propose` 回调 → `proposals.stage` → `stores.proposals` 插入 **pending**（此时 skills/mcpServers/tasks **不变**）。  
4. 工具结果回模型：「已出示确认卡 …，用户确认前不会保存。」  
5. 前端轮询 thread 后另拉 `GET …/proposals`，渲染 `ConfirmCard`。  
6. 用户选 scope → confirm / cancel。

**不**经 Message 特殊 kind；提议是独立 `proposals` 集合 + 会话内卡片，气泡正文仍是助手自然语言。

### 1.4 前端 ConfirmCard — 已齐（对齐旧稿）

`ui/conversation-pane.tsx` 内联 `ConfirmCard`：

- 标题按 kind → 技能 / MCP 服务 / 自动化任务  
- `.scope-options`：全局 \| 指定好友 + 好友多选  
- 未确认文案；取消 → `POST …/cancel` 丢草稿；确认 → `POST …/confirm`  
- 失败展示 `proposal.error`，卡可重试  

视觉对齐 `agent-chat-ui/confirm-card.html` + `styles` 的 `.confirm-card` / `.scope-opt`。

### 已知小差异（定稿时可顺手）

- task 写入仍要求 draft.`friendId`（或 friends scope 的首个）；与「作用域多选好友」语义略叠，确认时可用 `friendIds[0]` 作执行好友（现逻辑已如此）。  
- mcp 经提议确认写入时 `enabled: true`（对齐稿面「已启用 MCP」）。  
- `ProposalStatus` 含 `cancelled`，但 `cancel()` 是 **删除** 草稿而非改状态 — 与产品「取消丢弃」一致，类型字段可日后收紧。
