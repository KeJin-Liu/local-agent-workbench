# p0.9 长期分层记忆加深 — 技术方案（预研）

> 基线：`local-agent-workbench-p0.8`  
> 产品：长期分层记忆加深——**工作记忆 → 会话摘要 → 好友/项目长期层**；**写入与后续注入可感知**（超出 p0.4 蓝 chip 雏形）。  
> UI：**未定稿**。现有 `agent-chat-ui/summary-memory.html` / `long-term-memory.html` + shots 为 **p0.4** 双层演示，**没有** `layered-memory.html` / 写入提示 / 注入来源分层稿。本包只交方案，等 UI 再拷盘实现打 zip。

## 1. 现状结论（分层已有雏形，可感知不够）

### 1.1 三层对照（产品目标 vs 代码）

| 层 | 产品含义 | 现状 | 持久化 | 注入时机 | 可感知 UX |
| --- | --- | --- | --- | --- | --- |
| **工作记忆** | 本会话近期发言，短窗口 | **隐式**：`orchestrator` 把会话 `user/assistant` 历史整段塞进 `chatMessages`（`recall(..., 1)` 只取摘要，**不限窗**） | 即 `messages` 表，无独立实体 | 每回合始终带 | **无** chip / banner /「写入」提示 |
| **会话摘要** | 本会话压缩要点 | `Summary` + `memory/commit.ts` | `summaries`；每会话一条（同 id upsert） | `injectOnNextTurn` 时单独 system 消息 | 绿 `.chip-memory`「摘要已注入」+ 绿 `.memory-banner`「会话摘要已写入记忆…」+ 面板 |
| **好友/项目长期** | 跨会话事实 | `LongTermMemory` `scope=friend\|project` | `longTermMemories` + `ltmInjectPrefs` | 可注入条目 → 另一条 system（与摘要分开） | 蓝 `.chip-ltm`「长期记忆 · N」+ 蓝 `.memory-banner-ltm` + 管理面板 |

**结论**：摘要层与长期层在 **p0.3 / p0.4** 已落地并验收；「工作记忆」未命名、未可视化；p0.9 要做的是**分层可感知加深**，不是从零建库。

### 1.2 写入时机

| 路径 | 触发 | 行为 |
| --- | --- | --- |
| 摘要自动写 | `run.status === 'done'` → `persistTurnMemory` → `writeSummary(..., 'auto', true)` | 最近 ≤8 条 user/assistant 收成要点；**不另打模型**；取消/失败不写 |
| 摘要手动 | `POST …/summary` 再 `…/summary/inject` | 手动生成默认 `injectOnNextTurn=false`；「保留并注入」才开 |
| LTM 手动 | `POST /api/long-term-memories`；好友/群设置；聊天「管理记忆」 | `source` 默认 `manual` |
| LTM `source=auto` | 类型与 UI「自动提炼」tag **已预留** | **无**回合后自动提炼流水线；仅当 API 显式传 `source:'auto'` |

### 1.3 注入路径（编排顺序）

`session/orchestrator.ts` `startModel`：

1. 好友人设 `systemPrompt`  
2. **会话摘要** system（若 `injectOnNextTurn`）  
3. **长期记忆** system（`listInjectableForConversation` → `formatLongTermMemorySystemPrompt`）  
4. 提议工具提示  
5. **历史消息**（事实工作记忆）

摘要与 LTM 各一条 system，文案已区分「本会话摘要」vs「跨会话持久」。群聊 LTM：项目 `lineageId` + 首位好友；条目/作用域 `injectEnabled=false` 不进。

### 1.4 蓝 chip 雏形（p0.4）— 何谓「超出」

已有：

- 顶栏绿摘要 chip / 蓝 LTM chip（互斥开面板）  
- 聊天区绿/蓝 banner  
- LTM 单条注入勾选 + 作用域总开关  
- Asia/Shanghai 时间展示  

缺口（对齐产品「加深」）：

1. **无工作记忆层**可视（不知道「本回合带了多少近聊」）  
2. **写入瞬间**几乎无反馈（摘要靠 banner 静置；无 toast / 气泡旁「已写入 · 摘要|长期」）  
3. **注入来源**不分层展示（用户分不清本回合用了工作窗 / 摘要 / 哪几条 LTM）  
4. **层间晋升**未做（摘要要点 → 确认后升好友/项目长期；`source=auto` 空转）  
5. UI 稿仍是两页分立 demo，**无统一「分层记忆」面板**

```

```

## 2. 建议验收（供产品对齐；UI 定稿可改文案）

挡路建议三条（超出蓝 chip）：

1. **三层可辨**：主聊能看出工作记忆 / 会话摘要 / 好友·项目长期（chip、分层面板或等价），互不混色。  
2. **写入可感知**：摘要自动写入、LTM 新增（含将来 auto）有明确写入提示；取消回合仍不写。  
3. **注入来源可感知**：下一回合能看到「本回合注入了什么」（摘要开否、LTM 条数/作用域；工作窗条数可选）。

非挡候选：摘要→长期一键晋升确认门闩；工作记忆硬限窗（如最近 N 轮）并在面板显示。

## 3. 接线清单（UI 定稿后）

1. `cp -a local-agent-workbench-p0.8 local-agent-workbench-p0.9`  
2. 对照新 HTML/shot：  
   - 顶栏 / banner / 面板表达三层与「注入来源」  
   - 写入瞬间提示（不挡主聊发送）  
3. 后端最小增量（按稿裁剪）：  
   - **工作记忆**：暴露只读元数据（例如本回合将带的 recent 条数 / `coversUntil`），不必新建表  
   - **注入清单**：thread API 增加 `memoryInject: { working?, summary?, ltm[] }` 供 UI 渲染来源  
   - （若稿要晋升）`summary → LTM` 确认后 `createLongTermMemory`；仍走确认，不静默升层  
   - （若稿要自动提炼）在 `persistTurnMemory` 后挂钩启发式/模型提炼，`source:'auto'`，失败不挡主聊  
4. 单测：取消不写；注入顺序摘要先于 LTM；来源字段与 chip 计数一致。  
5. README 增 p0.9 验收；打 `local-agent-workbench-p0.9.zip`。

### 明确不做（本包除非产品改口）

- 云端向量库 / 跨设备同步  
- 把思维链（p0.7）当记忆层  
- 改通讯录 IA、市场/提议卡行为

## 4. 风险与依赖

- **强依赖 UI**：没有分层/写入/来源稿，容易只做「再添一个 chip」被判未超出 p0.4。  
- 工作记忆若限窗，要回归长会话质量；默认先「可感知计数」，限窗作非挡。  
- 自动升 LTM 需门闩，避免噪音事实污染好友层（对齐 p0.8 确认文化）。
