# p1.0 MVP 联调收口 — 技术方案

> 基线：`local-agent-workbench-p0.9`（48/48 已过，`local-agent-workbench-p0.9.zip`）  
> 产品范围（严格）：**Ollama/线上实聊冒烟** · **MCP 真 tools 一次调用** · **密码库引用 Provider** · **建好友+默认模型+MD 走通** · **不扩新功能**；联调露出交互洞再 @UI设计。  
> UI：定稿在 `/workspace/agent-chat-ui/`；本包无新稿。

## 1. 现状摸底（rg/Read 核对，非臆造）

### 1.1 Provider / 模型 / 实聊

| 项 | 路径 | 结论 |
| --- | --- | --- |
| 预设 | `src/storage/seed.ts` | Ollama `http://127.0.0.1:11434/v1`（`apiKeyPolicy:'none'` 启用）；LM Studio 启用；OpenAI/DeepSeek `required` 且默认停用 |
| 设置 UI | `src/ui/provider-settings.tsx` | Base URL、探测、默认模型、粘贴 Key、**保险库下拉引用** |
| 用例 | `src/app/providers.ts` | `normalizeBaseUrl`、`upsertProvider`（Key→vault）、`resolveProviderApiKey`、`probeEndpoint`、`assertProviderReady` |
| HTTP | `src/http/routes.ts` | `POST/PUT /api/providers`；`POST /api/providers/probe`（可带 providerId 从 vault 取 Key） |
| LLM 客户端 | `src/llm/client.ts` | 真 `fetch` → `{baseUrl}/models`、`/chat/completions`；解析 `tool_calls`；流式 SSE；无生产 mock 分支 |
| 编排 | `src/session/orchestrator.ts` + `src/server.ts` | `resolveApiKey`→vault；`runAssistantTurn` 真打上游；失败 `humanizeTurnError` 人话 |
| 模型选择 | orchestrator L133 | `input.model \|\| speaker.defaultModelId \|\| conversation.model \|\| provider.defaultModel`；全空 → 400「还没有指定模型…」 |
| 测试 mock | `test/*.test.ts` | 仅测试注入 `fetchImpl` / 本地 stub HTTP；**不挡** 生产实聊 |

**缺口**

1. **无自动化实聊冒烟**：本机/CI 未假定 Ollama；缺「探测到则跑、不可达则 skip」脚本。  
2. **群主种子无 `defaultModelId`**：冷启动必须先「探测 → 点选模型」才能发（有人话，属预期，但联调清单要写清）。  
3. **Provider 保存小瑕疵**：`provider-settings.tsx` 在 `vaultEntryId===''` 时**总是**带 `clearSecret:true`（对无 Key 的 Ollama 无害；新建路径多余；建议只在「取消关联 / 清空引用」时 clear）。

### 1.2 MCP 真 tools

| 段 | 路径 | 结论 |
| --- | --- | --- |
| SDK 连接 | `src/mcp/hub.ts` | 官方 SDK；`listTools` → OpenAI function；`callTool`；`catalogForChat` 对 **enabled** 服务 `ensureConnected`，连不上则跳过不炸整轮 |
| 服务层 | `src/app/mcp.ts` | upsert/connect/preview/enableFromCatalog；`catalogForChat()` 接 hub |
| 工具循环 | `src/session/tool-loop.ts` | 最多 4 轮；有 `tool_calls` → `callTool` → role=tool 回流 → 再补全 |
| 编排挂载 | `orchestrator` + `server.ts` | `mcpCatalog: () => mcp.catalogForChat()`；另挂 `workbench_propose` |
| Resources/Prompts UI | `mcp/catalog.ts` + `listResources/listPrompts` | **目录静态演示**，不是 live MCP；**与 tools 真调用无关** |
| 单测 | `test/tools.test.ts` | 只 stub 模型侧 `fetch`，**未**起真实 MCP server 验 `callTool` |

**缺口（联调核心）**

1. **缺「真 MCP 一次 call」离线冒烟**：市场条目依赖 `npx …` 外网包，本机易失败且非确定性。  
2. 启用但未连上时静默跳过工具 → 实聊可能「看起来没 tools」；需在验收里要求：预览/连接成功后再发，或看日志 `mcp 调用工具`。  
3. 建议交付：`scripts/mcp-echo-server.mjs` + vitest/node:test 走 hub 全链路（list→call），不依赖外网。

### 1.3 密码库引用 Provider

| 项 | 路径 | 结论 |
| --- | --- | --- |
| 数据模型 | `domain/types.ts` `Provider.vaultEntryId`；`VaultSecretRecord` | **已有**；明文 apiKey 不进提供方落盘 |
| 加密 | `vault/crypto.ts` + `vault/service.ts` | AES-GCM；`data/vault.key`；reveal 单独接口 |
| 迁移 | `migratePlaintextSecrets` + `storage/scrub.ts` | 旧明文/`apiKeySecretId` → `vaultEntryId` |
| UI | Provider「保险库引用」select；Vault 面板；MCP env/headers 同构引用 | **已有** |
| 测 | `test/vault.test.ts` | 粘贴只留引用、HTTP 无明文、MCP binding 引用 |

**缺口**：功能面已齐；p1.0 做**回归冒烟**（建条目 → Provider 选引用 → probe/发送用 reveal），不扩「系统钥匙串」等新能力。小修见 1.1 保存 clear 条件。

## 2. 验收清单（可勾选）

### A. Ollama / 线上实聊冒烟

- [ ] 设置 → 模型提供方：Ollama Base URL 为 `…/v1`，启用；点「探测模型」列出本机模型  
- [ ] 点选默认模型（或好友顶栏选模型写入 `defaultModelId`）  
- [ ] 与「群主」发一句，助手有流式/完整回复（非仅本地假数据）  
- [ ] 停掉 Ollama 再发：气泡/提示为人话（连不上 / 检查地址），非堆栈  
- [ ] （可选）OpenAI/DeepSeek：密码库建 api-key → Provider 引用 → 启用 → 探测 → 实聊一句  
- [ ] 自动化：`pnpm test` 中带 skip 的探测冒烟（不可达 skip，可达则 assert 模型列表非空）— 见 §4

### B. MCP 真 tools 一次调用

- [ ] 配置 stdio 指向 `scripts/mcp-echo-server.mjs`（或等价），启用并「预览工具」看到 `echo`  
- [ ] 聊天回合 tools 暴露给模型；模型发起一次 tool_calls 后，hub 真 `callTool`，结果回灌，最终有助手文本  
- [ ] 离线单测：hub connect → catalog → call 返回 echo 文本（不依赖 npx 市场包）  
- [ ] 明确：**Resources/Prompts 页仍可为目录静态预览**；本包不验收 live resources

### C. 密码库引用 Provider

- [ ] 密码库新建 api-key 条目（列表无明文）  
- [ ] Provider 下拉选该条目保存；落盘仅 `vaultEntryId`，无 `apiKey` 字段  
- [ ] 探测/发送不粘贴 Key 仍能带 Authorization（required 策略）  
- [ ] 取消关联后 required 提供方不可误启用乱打

### D. 建好友 + 默认模型 + MD

- [ ] 通讯录「＋」或 `workbench_propose` kind=friend：未确认不落库；确认后有好友；可带 defaultModelId  
- [ ] 顶栏改模型后同好友新会话沿用  
- [ ] 助手气泡 `**粗体**` 渲染为粗体、不露星号；列表/行内代码正常  
- [ ] `pnpm test` 含 `p081.test.ts` 全绿

### E. 回归 / 不做

- [ ] p0.9 分层记忆三层可辨、写入 toast、注入来源、摘要≠LTM 仍在  
- [ ] **不做**：新记忆策略、新 MCP 市场、云同步、非 OpenAI-compatible 协议、系统级钥匙串、扩 UI 新页

4. **手工联调**按 §2 A–D 勾选；洞再 @UI

## 5. 风险

| 风险 | 缓解 |
| --- | --- |
| Ollama/云 Key 环境不一 | 自动化 skip；验收以手工+日志为准 |
| 市场 `npx` 包失败被误判为「MCP 坏了」 | 验收强制用仓库内 echo server |
| 模型不调 tools | 人设/提示里点名「请调用 echo」；或单测只验 hub.call，不依赖模型意愿 |
| 5s 发送延迟误以为卡住 | 联调可 `SEND_DELAY_MS=0` 或测试 host `sendDelayMs:0` |
| Provider clearSecret 误清 | §3.1 小修 |
