# p0.7 思维链可折叠展示 — 技术方案（预研）

> 基线：`local-agent-workbench-p0.6`  
> 产品：与正式回复分流；**仅当模型产出 reasoning 时显示**；可折叠。  
> UI：截至本预研，`/workspace/agent-chat-ui/` **尚无** `thinking*.html` / `reasoning*` / 对应 shots（README 仍写「思维链折叠后置」）。**UI 已定稿（thinking-chain.html），本包已实现。**

## 1. 现状结论

### 1.1 Message / 持久化

`src/domain/types.ts` 的 `Message`：

- 有：`content: string`、`status`、`attachments?`、`kind?` …
- **无**：`reasoning` / `thinking` / `contentParts`

消息整对象 `put` 进 JSON 库（`messages` collection），加可选字段即可向前兼容，无需迁移脚本。

### 1.2 LLM 流式（服务端 → 上游 OpenAI 兼容）

| 位置 | 现状 |
| --- | --- |
| `POST {baseUrl}/chat/completions` `stream:true` | `src/llm/client.ts` `chatStream` |
| SSE | 按行 `data: …`，直到 `[DONE]` |
| `parseSseLine` | **只读** `choices[0].delta.content`（非空字符串才 yield） |
| `ChatDelta` | `{ content: string }` — **无 reasoning** |
| `chat()` 非流式 | 只读 `message.content` + `tool_calls` |

工具回合（有 MCP/propose 工具）走非流式 `chat()`，最终文本一次性返回；无工具时才 `chatStream` + `onProgress`。

### 1.3 编排与落库

`session/tool-loop.ts` → `onProgress(content)` 只推**正文累计**。  
`session/orchestrator.ts`：助手消息先 `content:'' status:'streaming'`，进度里反复 `put({ content: text, status:'streaming' })`，结束 `complete`。  
**全程不碰 reasoning。**

### 1.4 前端刷新与气泡

- **无浏览器 SSE**。`conversation-pane.tsx` 在 run `pending|running` 时每 **400ms** 拉 `GET /api/conversations/:id/thread`，用返回的 `messages` 整表替换。
- 助手气泡：`MessageBubbleBody` 渲染 `message.content` + attachments；流式时 `status==='streaming'` 显示「· 生成中」。
- 因此：只要服务端把 `reasoning` 写进 Message，前端轮询即可拿到，**不必新开事件通道**（流式体感仍取决于 400ms 轮询）。

### 1.5 Send API（与思维链无关，但同包非挡）

- `POST /api/conversations/:id/send`：`{ text, attachmentIds?, … }`
- 后端已允许 **仅附件无正文**（`orchestrator`：`if (!text && !attachments) throw`）。
- 前端发送钮仍：`disabled={… \|\| draft.trim().length === 0}` → **忽略已就绪附件**（p0.6 产品非挡）。
- 稿面 `rich-media.html` 有双钮（回形针 + 图片）；实现已合并为一个 `attach-btn`（产品要求保持合并）。

### 1.6 UI 定稿缺口

```
agent-chat-ui/  → 无 thinking*.html / reasoning* / shots/*think*
README          → 「思维链可折叠展示 — 本包不做」
```

**等 UI 出稿（建议 `thinking.html` + `shots/thinking.png`，以及 styles 里折叠块 class）再从 p0.6 拷 `local-agent-workbench-p0.7` 全量接线。**

## 2. 推荐字段形状

### 2.1 领域（落库 + thread API）

```ts
export type Message = {
  // …既有字段
  content: string
  /**
   * 模型思维链 / reasoning。仅助手消息；无产出时不写该字段。
   * 不并入 content，便于与正式回复分流、折叠展示。
   */
  reasoning?: string
}
```

不引入 `contentParts` 数组（本阶段够用；避免改气泡渲染与历史注入逻辑）。若日后多模态 parts，再演进。

### 2.2 LLM 增量

```ts
export type ChatDelta = {
  content?: string
  reasoning?: string
}

export type ChatResponse = {
  content: string
  reasoning?: string
  toolCalls: ToolCall[]
  model: string
  finishReason?: string
}
```

`parseSseLine` 归一化（兼容常见上游）：

| 上游字段 | 映射到 |
| --- | --- |
| `delta.content`（string） | `content` |
| `delta.reasoning_content`（DeepSeek reasoner 等） | `reasoning` |
| `delta.reasoning`（部分兼容网关） | `reasoning` |
| `message.reasoning_content` / `message.reasoning`（非流式） | `reasoning` |

空串不 yield；`content`/`reasoning` 可同 chunk 并存。忽略未知字段。

### 2.3 进度回调

```ts
onProgress?: (state: { content: string; reasoning: string }) => Promise<void>
```

`streamText` 分别累加；`orchestrator`：

```ts
await repos.messages.put({
  ...assistantBase,
  content: state.content,
  ...(state.reasoning ? { reasoning: state.reasoning } : {}),
  status: 'streaming',
})
```

完成时同样持久化 `reasoning`（有则写）。取消 `deleteByRun` 一并清掉，行为不变。

### 2.4 回灌模型上下文

`contentForModel(item)` **默认只送 `content`**，不把 `reasoning` 拼进历史（避免胀上下文、避免部分模型拒绝）。若某提供方日后要求带 thinking，再加开关。

## 3. UI 接线约定（待定稿对齐）

建议 IA（与产品「分流 + 可折叠 + 有才显示」一致）：

1. 助手气泡内、**正文上方**：折叠块（如 `<details class="think-block">` 或稿面指定 class）。
2. 摘要行：「思考过程」/「已思考」；默认 **折叠**（流式时可短暂展开或显示「思考中…」，定稿为准）。
3. `!message.reasoning?.trim()` → **整块不渲染**（含流式尚未产出时）。
4. 正式回复仍走现有 `.bubble` / `MessageBubbleBody`；reasoning 不得混进 `content` 字符串。
5. 通讯录 / 主壳 IA 不变；不挡 Enter、`/new_chat`、附件发送。

样式与 class **以 UI 定稿 HTML/CSS/shots 为准**，实现时对照拷贝，不自创视觉。

## 6. 风险与非目标

| 项 | 说明 |
| --- | --- |
| 提供方差异 | 仅部分模型（如 deepseek-reasoner）吐 reasoning；普通 chat 无字段 → UI 隐藏即可 |
| 工具回合非流式 | 有工具时目前不流式；若响应带 `reasoning_content`，仍应写入最终 Message |
| 加密/隐藏 thinking | OpenAI o 系列部分只给摘要或不可见；无明文则当无 reasoning |
| 非目标 | 不改主壳 IA；不做「强制展开」全局设置（除非稿面要求）；不做 contentParts 重构 |
