## 1. p1.0 摸底（rg/Read）

### 1.1 Friend 模型与存储

| 项 | 路径 | 结论 |
| --- | --- | --- |
| 类型 | `src/domain/types.ts` `Friend` | 有 `providerId` / `defaultModelId`；**无** `workspacePath` / `codePermission` |
| 用例 | `src/app/friends.ts` `upsertFriend` | 写 name/description/systemPrompt/avatar/provider/defaultModelId |
| 仓库 | `src/storage/repos/friends.ts` | 通用 collection，字段随类型走 |
| Schema | `src/storage/schema.ts` | `friends` 在 `STORE_NAMES`；无强制列迁移，缺字段按 undefined |

**本包**：在 `Friend` 上加可选 `workspacePath?: string`、`codePermission?: CodePermission`（默认语义 `workspace-write`，未绑定时三类工具全禁）。

### 1.2 proposals / ConfirmCard 门闩

| 项 | 路径 | 结论 |
| --- | --- | --- |
| 类型 | `ProposalKind = 'skill'\|'mcp'\|'task'\|'friend'` | 确认前只存 `proposals`；confirm 才写本体 |
| 服务 | `src/app/proposals.ts` | `stage` → pending；`confirm` 整笔写；`cancel` 删草稿；失败不脏写 |
| 内置工具 | `PROPOSE_TOOL` / `workbench_propose` | 挂进 orchestrator 工具表 |
| UI | `conversation-pane.tsx` `ConfirmCard` | 拉 pending → 确认/取消；好友卡可改字段 |

**本包决策**：**新集合 `codeActions`**（不硬塞进 `ProposalKind`）。写文件 / shell 的 draft 形状、确认副作用（磁盘 write / spawn）与 skill/mcp 不同；单独类型更清晰。交互语言对齐 ConfirmCard（确认前不落盘、取消丢弃、失败可重试）。

### 1.3 tool-loop / orchestrator 挂工具

| 项 | 路径 | 结论 |
| --- | --- | --- |
| 循环 | `src/session/tool-loop.ts` | `MAX_TOOL_ROUNDS=4`；有 tools → chat → tool_calls → `callTool` → role=tool |
| 编排 | `src/session/orchestrator.ts` L299–323 | `mcpCatalog()` + 可选 `PROPOSE_TOOL`；`callTool` 先拦 propose 再交 MCP |
| MCP hub | `src/mcp/hub.ts` `ToolCatalog` | `{ tools: OpenAiTool[]; call(name, args, signal) }` |
| 宿主 | `src/server.ts` | 注入 `mcpCatalog` / `propose` |

**本包挂法**：仿 propose——新增 `codeToolsCatalog(friend)`：只读工具直接执行；写/shell 工具只 `stage` CodeAction 并返回「已出示确认卡」文案。`callTool` 分支优先匹配 `workbench_fs_*` / `workbench_shell`。

## 2. 数据模型

### 2.1 Friend 扩展

```ts
export type CodePermission = 'read-only' | 'workspace-write' | 'danger-full-access'

// Friend 新增：
workspacePath?: string          // 绝对路径；未设 = 未绑定
codePermission?: CodePermission // 缺省按 workspace-write 解释；未绑定仍全禁工具
```

- 绑定/切换：好友设置 API `PUT` 带 `workspacePath`（规范化后落库）。  
- `danger-full-access`：写 / 删 / shell 在 Workspace 内直接执行，不再逐次确认；仍不放行越界路径。

### 2.2 CodeAction（新 store）

```ts
export type CodeActionKind = 'write' | 'shell'
export type CodeActionStatus = 'pending' | 'confirmed' | 'cancelled' | 'failed'

export type CodeAction = {
  id: string
  conversationId: string
  friendId: string
  runId?: string
  kind: CodeActionKind
  /** 展示用短摘要（相对路径或命令头） */
  summary: string
  status: CodeActionStatus
  /** write: { relativePath, content, unifiedDiff? }；shell: { command, cwd, timeoutMs? } */
  draft: Record<string, unknown>
  /** confirm 后：write 记 bytes；shell 记 exitCode / stdoutTail / stderrTail */
  result?: Record<string, unknown>
  error?: string
  createdAt: number
  updatedAt: number
}
```

`WorkbenchStores` + `STORE_NAMES` 增加 `codeActions`。

### 2.3 工具时间线

```ts
export type CodeToolTimelineEntry = {
  id: string
  conversationId: string
  runId?: string
  friendId: string
  toolName: string
  /** 相对路径 / 命令摘要 */
  detail: string
  outcome: 'ok' | 'denied' | 'pending' | 'confirmed' | 'cancelled' | 'error'
  resultSummary?: string
  createdAt: number
}
```

本包可先：**内存/落库数组 `codeToolEvents`**（或挂在 Message 旁的独立 store）；UI 接线时按 conversationId 拉取。最低验收：一次读、一次写确认、一次命令确认可回看。

## 3. 工具名与契约

| 工具名 | 权限 | 行为 |
| --- | --- | --- |
| `workbench_fs_list` | 绑定 + 非禁 | `{ path? }` 相对 workspace；列目录 |
| `workbench_fs_read` | 同上 | `{ path }` 读文本（超大截断） |
| `workbench_fs_grep` | 同上 | `{ pattern, path?, glob? }` 简单内容搜索 |
| `workbench_fs_write` | `workspace-write` 或 danger（本包同） | **只 stage** CodeAction(write)；返回 pending id |
| `workbench_shell` | 同上 | **只 stage** CodeAction(shell)；cwd 强制 = workspace |

未绑定：三类工具均返回人话「请先在好友设置里绑定 Workspace」，**不触盘**。  
`read-only`：写/shell 工具拒绝人话。  
越界：resolve 失败 → 人话拒绝。

HTTP（UI 接线时）：

- `GET /api/conversations/:id/code-actions`  pending 列表  
- `POST /api/code-actions/:id/confirm` → writeFile / spawn  
- `POST /api/code-actions/:id/cancel` → 丢弃  
- `PUT /api/friends/:id` 扩展 workspace/permission  
- `GET /api/conversations/:id/code-timeline`（可选）

## 4. 路径沙箱

`src/app/code-workspace.ts`（纯函数 + fs 无关 resolve）：

1. `normalizeWorkspaceRoot(raw)`：`path.resolve`，拒绝空。  
2. `resolveInWorkspace(root, relativeOrAbs)`：  
   - 相对路径基于 root join；绝对路径也必须落在 root 下（`path.resolve` 后 `relative` 不以 `..` 开头且不跳出）。  
   - 符号链接：本包 **resolve 实路径可选**；MVP 以规范化字符串边界为主，测试覆盖 `../` 与绝对越界。  
3. 失败抛 `AppError(400, '只能访问已绑定 Workspace 内的路径…')`。

## 4.1 产品澄清：工作目录可选（2026-11-03）

- 好友 `workspacePath` **可选**。未选 = **不启用**本机读写/shell；**聊天照常**。

- `danger-full-access`：写 / 删 / shell 直接执行，不弹确认；仍不能越出已绑定目录。

## 7. 测例清单

1. **沙箱**：相对 OK；`../` 拒绝；绝对越界拒绝；空 root 拒绝。  
2. **未绑定**：list/read/grep/write/shell 均禁，磁盘无访问。  
3. **只读越界**：绑定后 `../secret` 拒绝。  
4. **write**：stage 后目标文件内容不变；confirm 后变更可断言；cancel 后不变。  
5. **shell**：stage 不 spawn；confirm 后有 exitCode；cancel/拒绝未执行（可用 sentinel 文件测）。  
6. **read-only 档**：write/shell stage 被拒。  
7. （接线后）时间线至少 3 条可查。
